# 🎾 앵그리 테니스 클럽 대진표 생성기

클럽 주간 모임의 복식 대진표를 자동으로 만들어주는 도구입니다.

## 🔗 앱 주소 (온라인)

**https://lakeastern.github.io/angry/**

휴대폰·PC 어디서나 위 주소로 바로 접속해 사용할 수 있습니다(실시간 대회·공유 링크는 이 주소 기반). 즐겨찾기 해두세요.

## 바로 사용하기

**`dist/앵그리대진표.html` 파일을 더블클릭**하면 브라우저에서 바로 열립니다.
설치·인터넷 연결이 필요 없고, 휴대폰으로 파일을 보내서 열어도 동작합니다 — 다른 사람에게 파일 하나만 보내도 대진표를 만들 수 있습니다.

> 파일로 열면 **대진표 생성·수동 조정·결과 입력·랭킹 보기**는 모두 되지만,
> **실시간 대회와 클라우드 랭킹(공유)** 은 온라인 주소에서만 동작합니다(파일 주소에는 Firebase 인증 도메인이 없음).
> 이때 관련 버튼(실시간 대회·관리자 로그인)과 **대진표 공유 링크·관리자 비밀번호**도 자동으로 숨겨집니다.
> 공유 링크는 온라인 앱 주소로 연결되는 방식이라 파일 배포본에서는 의미가 없고 클럽 앱으로 이어지므로 아예 제공하지 않습니다 —
> 만든 대진표는 **📷 이미지 저장**으로 공유하세요. 덕분에 클럽 외부인에게 파일만 전달해도 클럽 데이터와 완전히 분리됩니다.

1. 모임 유형 선택 — **정기모임**(a·b코트 게임 + c코트 레슨, 게임온리 라운드는 c코트도 게임), **게임데이**(3코트 전부 게임), 또는 **앵그리대회**(별칭 대진표 + 현장 제비뽑기)
2. 오늘 참석자 번호 선택 (남 1~9, 여 A~I — 번호가 빠를수록 실력 상위)
3. 필요하면 개인 특성(게임선호⚡/신규회원🔰/혼복선호💞)과 지각·조퇴 라운드 설정
4. **대진표 생성** — 마음에 안 들면 **다시 섞기**
5. 수동 조정: 대진표에서 선수 이름 두 개를 차례로 누르면 자리를 맞바꿈 (규칙 위반 시 경고 표시)
   - **멤버 교체**: 대진표를 만든 뒤 멤버를 잘못 넣었다면 다시 짤 필요 없이, ③ 오늘 참석자에서 참석자를 **길게 꾹 누르고**(PC는 우클릭) 바꿀 멤버를 누르세요.
     미참석자를 누르면 그 사람이 대신 참석하며 대진표의 자리(지각/조퇴 라운드 포함)를 그대로 이어받고, 다른 참석자를 누르면 두 사람의 자리가 서로 바뀝니다.
     성별이 다르면 확인 후 교체(잡복은 경고로 표시), 앵그리대회는 별칭 배정만 바뀌므로 같은 성별끼리만, 실시간 대회 진행 중인 대진표는 교체할 수 없습니다.
6. **인쇄** 버튼으로 출력

마지막에 선택한 참석자·특성은 브라우저에 저장되어 다음 주에 그대로 불러옵니다.

## 앵그리대회 모드 (별칭 대진표)

매분기 대회용. 참석자의 남/여 수만큼 **남1·남2…/여1·여2… 별칭으로 대진표를 미리 준비**하고, 당일 현장 제비뽑기로 각 별칭에 실제 멤버를 배정합니다.

- 별칭엔 랭킹이 없으므로 게임 점수차 상한·라이벌 라운드·혼복 위주·랭커 라운드 설정은 숨겨집니다 (규칙은 게임데이 기반: 3코트, 인당 게임 수, 인당 최소 혼복). "성별 구분 없이 편성"(잡복 허용, 기본 꺼짐)은 극단적 성비 대비로 게임데이와 동일하게 제공됩니다.
- 대진표 아래 **별칭 배정 패널**: 참석자별 별칭 드롭다운(동성만, 이미 배정된 별칭은 숨김 → 1:1 자동 중복방지). **🎲 제비뽑기** 버튼으로 무작위 배정(현장 추첨 대체/기록).
- **별칭 ↔ 실명 토글**로 대진표에 실제 이름을 반영해 볼 수 있습니다.
- 공유 링크 뷰어는 기본 별칭 표시, 배정을 마친 뒤 공유하면 뷰어에서도 실명 토글이 가능합니다.
- (경기 결과 입력·앵그리랭킹 누적은 추후 확장 예정.)

## 실시간 대회 (라이브 스코어)

게임데이·앵그리대회에서 **당일 순위를 실시간으로** 볼 수 있습니다. 게임이 끝날 때마다 참가자가 각자 점수를 입력하면 모두의 화면에서 순위가 즉시 갱신됩니다.

1. 대진표 생성 → (앵그리대회는) 제비뽑기로 별칭 배정 → **"🔴 실시간 대회 시작"** → 공유 링크(`#live=…`)가 복사됩니다
2. 링크를 단톡방에 공유 → 멤버들이 열면 **대진표 + 실시간 순위**가 보이고, 각 게임 칸에 점수를 입력할 수 있습니다
3. 점수 입력 즉시 모두의 순위가 자동 갱신 (12게임 중 일부만 끝나도 현재 1위 확인)
4. 관리자 화면의 **"결과 확정·저장"** 으로 최종 결과를 앵그리랭킹(누적)에 반영하고 실시간 대회를 종료합니다

- 관리자 화면에도 **실시간 진행 패널**(입력 현황·순위표·경기별 스코어)이 표시되어, 링크 페이지로 가지 않아도 진행 상황을 봅니다. 순위표는 개별 대회와 동일하게 순위·이름·종합점수·승-패·득·실·득실차·경기·경기별(득실)을 모두 보여줍니다.
- 관리자가 **새로고침**해도 진행 중인 실시간 대회로 자동 복귀합니다(같은 링크 유지). 관리자 진행바의 **"실시간 화면 열기"**는 새 탭으로 열리고(관리자 화면 유지), 그 라이브 탭의 **"✕ 관리자 화면으로 (이 창 닫기)"**를 누르면 탭이 닫히며 원래 관리자 탭으로 돌아옵니다. 링크로 직접 연 멤버 화면은 **"← 앵그리 앱으로"**로 앱 첫 화면에 갑니다.
- 실시간 화면은 앵그리대회의 경우 기본 **"실명 보기"**로 표시됩니다(별칭 보기로 전환 가능). 멤버가 링크에서 입력한 점수는 관리자 화면의 **"📝 결과 입력"** 칸에도 실시간 반영되고, 관리자가 그 칸에서 고치면 멤버 화면에도 반영됩니다.
- **"대회 중단"** 으로 저장 없이 종료할 수 있습니다(공유한 링크는 더 이상 동작 안 함). 앵그리대회는 **"결과 확정·저장"** 으로 누적 랭킹에 반영하며 종료됩니다.
- 안전장치: 제비뽑기 전 시작 시 경고, 실시간 대회 중복 시작 차단, 동점(오타) 게임은 저장에서 자동 제외(전체 저장을 막지 않음), 관리자가 "대회 종료"하면 멤버 링크 화면도 자동으로 "종료됨" 안내 + 입력 차단.
- **로그인 없음** — 링크(추측 불가한 랜덤 ID)를 아는 사람이면 점수를 입력할 수 있는 신뢰 기반입니다. 최종 확정은 관리자 화면에서만 하므로 누적 랭킹은 안전합니다.
- 인터넷 연결이 필요하며(Firebase Firestore), 미설정·오프라인이면 이 기능만 비활성화되고 나머지는 그대로 동작합니다.

## 클럽 명단은 클라우드에서 (관리자 전용)

**① 클럽 명단 관리**의 명단은 관리자가 **🔑 관리자 로그인**(Google)을 하면 Firestore(`club/roster`)와 동기화됩니다.

- 관리자 기기에서 명단을 고치면 다른 관리자 기기에도 반영됩니다. 클라우드가 비어 있으면 그 기기의 명단으로 최초 등록됩니다.
- 명단에는 **실력 순위·개인 특성**이 담겨 있어 **관리자만 읽고 쓸 수 있습니다**(멤버는 대진표·랭킹만 봅니다).
- **배포용 단일 파일(file://)이나 로그인하지 않은 기기의 명단은 이 기기에만 저장**되며 클럽 명단에 영향을 주지 않습니다. 그래서 파일을 클럽 외부인에게 나눠줘도 안전합니다.
- **공유 링크는 명단을 옮기지 않습니다.** 예전에는 링크에 명단이 암호화되어 담겨 받는 기기의 명단을 덮어썼는데(사고 원인), 이제 링크에는 대진표와 재생성용 구성만 담깁니다.

## 공유와 권한

클럽 명단·랭킹은 클라우드(관리자 전용/공개 조회), 그 밖의 설정·대진표 버전은 각 기기 브라우저에 저장되며, 공유는 링크로 합니다.

- **📤 대진표 공유 링크** — 매주 단톡방에 올리는 용도. 받는 사람은 **보기 전용 화면**(대진표 + 인쇄)만 봅니다.
  **링크는 명단을 옮기지 않습니다** — 대진표와 재생성용 구성(설정·시드)만 담기며, 구성은 관리자 비밀번호로 암호화(AES-GCM)됩니다.
- **관리자 비밀번호** (고급 설정에서 지정) — 비밀번호를 아는 사람이 보기 화면에서 "🔑 관리자 모드"로 들어가면
  그 대진표가 자기 기기의 버전 목록에 추가되어 이어서 편집·재생성할 수 있습니다. **명단은 덮어쓰지 않습니다.**
- 비밀번호를 변경하면 이전 링크의 구성은 복원할 수 없습니다(대진표 보기는 계속 가능).
- 참고: 대진표 자체(이름 포함)는 링크를 가진 누구나 볼 수 있습니다. 명단의 실력 순위·개인 특성은 클라우드에서 관리자만 봅니다.

## 대진 규칙 (우선순위 순)

1. 한 라운드에 1인 1게임, 게임코트는 항상 채움 **(하드)**
2. 잡복 금지 — 남복/여복/혼복만 **(하드)**. 단 "성별 구분 없이 편성"을 켜면 잡복을 허용하되, **남복 팀 vs 여복 팀(남남 vs 여여) 대진만은 항상 금지** (게임데이·앵그리대회 공통, 팀 분할로 항상 회피)
3. 같은 파트너 중복 0회 **(하드)** — 성별 무시 편성에서 남복vs여복을 없애기 위해 불가피하면 파트너 중복이 이보다 후순위로 완화될 수 있음(배너 표시)
4. 게임 수 균등(차이 ≤1), 2라운드 연속 결장 금지
5. 정기모임: 3라운드 내 전원 1회 레슨 로테이션 (게임온리 라운드를 뺀 첫 레슨 라운드 3개 기준)
   - **게임온리 라운드**(고급 설정, 기본 1라운드): 코치 일정에 따라 c코트도 레슨 없이 게임으로 운영 (최대 3코트).
     12명을 넘으면 남는 인원은 휴식 — 대진표 c코트 칸 구석에 회색 작은 글씨로 표시됩니다. 게임온리 라운드는 라운드 순서 최적화에서도 자리가 고정됩니다
6. 게임데이·앵그리대회: **인당 게임 수 우선**(기본 켜짐) — 전원이 목표 게임 수를 채우도록 최우선 배정.
   덜 중요한 제약부터 자동 완화하고, 성비가 크게 치우쳐 불가피할 때만 잡복을 **최소 게임 수**로 허용(배너 표시). 끄면 규칙 우선(잡복 0, 게임 수 편차 가능). 인당 최소 혼복 게임 수도 설정(기본 1회)
7. 랭커 라운드(설정, 기본 2): 상위 랭커끼리 게임 — 남복/여복은 상위 5명 중 4명, 혼복(혼복 위주 라운드와 겹칠 때)은 남녀 각 상위 3명 중 2명을 매번 랜덤 선정
8. 라이벌 라운드(설정, 기본 1·2·3): 비슷한 실력 4명이 한 게임 (팀은 균형 분할)
9. 같은 상대 재대면 최소화(상한 설정, 기본 2번) + 팀 합산 점수 균형
10. 개인 특성 반영 (정기모임)
11. 게임 유형 — 혼복 위주 라운드(설정, 기본 1·3)는 혼복 위주, 나머지는 동성복식 위주. 게임데이는 동성복식 위주
12. 레슨 그룹 실력 유사성

게임데이·앵그리대회는 **코트 수**를 기본 자동(인원 맞춤 1~3)으로 정하되, 고급 설정에서 **1~4코트로 직접 지정**할 수 있습니다(코트 예약 사정 등). 4코트는 16명 이상일 때 쓸 수 있고, 인원상 한 라운드를 다 못 채우는 코트 수는 자동으로 줄이며 안내합니다.

지킬 수 없는 조합(예: 남자 1명, 12명 게임데이에 남자 홀수)은 이유와 대안을 안내하고,
불가피한 완화(연속 결장 등)는 파란 배너로 표시됩니다.

## 개발

순수 JavaScript(ESM), 빌드 도구·외부 의존성 없음. 개발에만 Node.js 18+ 필요.

```
npm test             # 엔진 단위 테스트 — 8~18명 남녀 전 조합 + 엣지 케이스 (481 tests)
npm run test:e2e     # 브라우저 E2E — 실제로 렌더되고 클릭이 동작하는지 (10 시나리오)
npm run test:e2e:dist  # 배포 번들(dist/) 을 같은 시나리오로 검증
npm run build        # dist/앵그리대진표.html 단일 파일 생성
```

E2E 는 Playwright(파이썬)를 쓴다. 최초 1회만 준비하면 된다:

```
pip install playwright && python -m playwright install chromium
```

단위 테스트가 **엔진 로직**을 본다면 E2E 는 **화면**을 본다. 엔진은 멀쩡한데 앱이
죽는 종류의 사고 — 대표적으로 `build.mjs` 의 `ENGINE_FILES` 에 새 엔진 파일을 빠뜨려
`computeRanking` 이 미정의가 되는 회귀 — 를 잡는 것이 목적이다.
`npm run test:e2e:dist` 는 실제로 배포되는 번들을 검사하므로 배포 전에 돌리면 좋다.

E2E 는 **Firebase 를 네트워크 레벨에서 차단**한 상태로 돌아간다. 운영 Firestore 의
클럽 명단·경기 기록(실명)을 테스트가 읽지 않게 하고, 네트워크 상태에 결과가
흔들리지 않게 하기 위한 것이다. 그래서 테스트 중 앱은 오프라인 모드로 동작한다.

```
engine/
  scheduler.js   공개 API: generateSchedule(config)
  planner.js     라운드·코트 계획, 실현 가능성 사전 검사 (패리티/파트너 풀)
  construct.js   라운드별 구성: 결장자 선정 → 페어링 백트래킹 → 매치업
  optimize.js    사전식 비용 튜플 + 로컬 서치 (하드 제약 보존 스왑)
  validate.js    검증기 — 엔진 자기검증·UI 수동편집 경고·테스트 공용
  rng.js         시드 PRNG (같은 시드 = 같은 대진표)
app.js           웹 UI (index.html은 로컬 서버에서 모듈로 로드)
build.mjs        엔진+UI를 단일 HTML로 번들
test/            node --test (파일은 .mjs — 일부 윈도우 환경에서 한글 경로 .js 엔트리 크래시 회피)
test/e2e/        Playwright 브라우저 E2E (파이썬, run_e2e.py 단독 실행 — 서버도 스스로 띄운다)
```

## 앵그리랭킹 (경기 결과·순위)

앵그리대회 결과를 입력해 멤버별로 누적 랭킹을 매깁니다.

1. 앵그리대회 대진표 생성 → 제비뽑기로 별칭 배정 완료
2. 결과 대진표에서 **"📝 결과 입력"** → 각 게임에 스코어(예: 6 : 4) 입력
3. **"이 대회 결과 저장"** → 별칭이 실제 멤버로 확정되어 저장, **🏆 앵그리랭킹** 카드에 누적
4. **기간**을 골라 봅니다 — **지난 1년(기본, 최근 12개월)** · **연도별(2026년…, 연말 기준)** · 전체 · 대회별 단일.
   **기준**도 고를 수 있습니다 — **누적**(승수 우선)과 **평균**(승률 → 경기당 득실차, 참석 횟수 무관 비교).
   평균 기준에서는 표본이 적은 인원이 상위를 차지하지 않도록 **최소 경기 수**(기본 4경기)를 정하고, 미달자는 순위 없이(–) 아래에 표시합니다.
   **👥 현재 명단만** 토글을 켜면 **현재 클럽 명단의 정회원만**(게스트 제외) 줄 세워 순위를 다시 매깁니다 — 탈퇴자·게스트·과거 참가자를 시상 대상에서 빼고 볼 때 씁니다. 지난 경기 기록(승패·득실)은 그대로 반영되며, 순위 대상만 걸러집니다.
5. **누적 기준** 정렬은 **승수 우선 → 패 적은 순 → 득실차 → 득점** (리그 순위표 방식). 같은 승수면 **패가 적은(무가 많은) 사람이 득실차와 무관하게 위** — 예: 3승1무0패가 3승0무1패보다 항상 위. 종합점수 = 승수 × 3. **동점(무승부)** 게임도 기록·집계됩니다(경기수·득실·"무"에 반영, 승/패 아님 → 종합점수엔 미반영). 무승부가 있으면 승-패 대신 **승-무-패**로 표기
6. **대회별 단일(당일 시상)** 랭킹에는 🥇🥈🥉 메달과 선수별 경기 스코어(예: `60 63 61 63`, 이긴 게임 초록)도 표시
7. 저장된 대회는 개별 삭제 가능(랭킹 자동 재계산), **백업 내보내기/가져오기**(JSON)로 이동·복원
8. **점수 반영 게임 수 상한**: 대회별 단일 보기에서 "점수 반영 게임 수"를 정하면 각 선수의 **앞선 N게임까지만** 순위에 반영됩니다. 인원×게임수가 4로 안 나눠떨어져 일부가 목표보다 1게임 더 한 경우(전원 최소 목표 게임 보장) 목표 게임 수까지만 반영하거나, 코트 시간이 부족해 게임 수가 제각각일 때 모두 같은 게임 수까지만 반영하는 데 씁니다. 기본값은 설정한 인당 게임 수.

### 클라우드 랭킹 (Firebase)

랭킹은 **Firestore가 원본**이라 멤버들이 각자 기기에서 앱 주소만 열어도 같은 누적 랭킹을 봅니다.

- **조회**: 로그인 없이 누구나. 오프라인이면 마지막으로 받아둔 내용을 캐시로 보여줍니다.
- **저장·수정·삭제**: 앵그리랭킹 카드의 **🔑 관리자 로그인**(Google, 기기당 1회)을 한 관리자만 가능. 로그인하면 결과 저장 시 자동으로 클라우드에 반영되고, 이 기기에만 있던 기록은 **☁ 올리기** 버튼으로 한 번에 동기화합니다.
- 과거 대회 이력(엑셀 이관분)은 실명이 포함되므로 **공개 저장소에 넣지 않고 Firestore에만** 보관합니다. `⬆ 가져오기`로 시드 JSON을 한 번 넣으면 이후 클라우드에서 관리됩니다. 이때 선수 이름은 현재 명단의 멤버로 자동 연결되어 새 대회 기록과 합산됩니다.
- 팀 구성 정보가 없는 과거 기록은 **선수별 스코어 형식**(`playerGames`)으로 저장되며, 순위·득실·경기별 로그가 동일하게 계산됩니다.

**Firebase 콘솔 설정** (최초 1회): ① Authentication → Sign-in method → **Google 사용 설정**
② Authentication → Settings → 승인된 도메인에 **`lakeastern.github.io`** 추가
③ Firestore → 규칙에 아래를 게시(관리자 이메일을 본인 것으로):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null
        && request.auth.token.email_verified == true
        // 관리자를 여럿 두려면 콤마로 나열 (실제 주소는 저장소에 남기지 않고 콘솔에만 입력)
        && request.auth.token.email in ['관리자1@gmail.com', '관리자2@gmail.com'];
    }
    function isValidEvent(d) {
      return d.keys().hasAll(['mode', 'status'])
        && (d.mode == 'tournament' || d.mode == 'monthly')
        && (d.status == 'live' || d.status == 'final')
        && d.size() <= 40;
    }
    function isValidGame(d) {
      return d.size() <= 12
        && (!('a' in d) || (d.a is int && d.a >= 0 && d.a <= 99))
        && (!('b' in d) || (d.b is int && d.b >= 0 && d.b <= 99));
    }
    // 실시간 대회(임시) — 링크(랜덤 ID)를 아는 사람만
    match /events/{eventId} {
      allow get: if true;
      allow list: if false;
      allow create, update: if isValidEvent(request.resource.data);
      allow delete: if true;
      match /games/{gameId} {
        allow read: if true;
        allow create, update: if isValidGame(request.resource.data);
        allow delete: if true;
      }
    }
    // 앵그리랭킹(영구 기록) — 누구나 조회, 관리자만 쓰기
    match /results/{resultId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    // 클럽 명단 — 실력 순위·개인 특성이 담겨 있어 관리자만 읽고 쓴다
    match /club/{docId} {
      allow read, write: if isAdmin();
    }
  }
}
```

게임데이 결과 집계도 추후 포함 가능.
